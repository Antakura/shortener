# SKILLS.md

Инженерные стандарты, шаблоны выдачи (ревью, декомпозиция, выбор ветки) и практические разборы оптимизации кода.

---

## 1. Стандарты кода (Coding Standards)

### 1.1. Python 3.12+ и качество кода
- **Типизация:** использовать современный синтаксис (`X | Y`, `list[str]`, `Annotated[...]`) и аннотировать все публичные функции/методы.
- **Логирование вместо `print()`:** использовать стандартный `logging` (или `structlog`), чтобы управлять уровнями логов и видеть контекст в Docker/Celery.
- **Обработка ошибок:** не глушить исключения пустым `except Exception: pass`; в сервисах выбрасывать понятные доменные исключения и маппить их на HTTP-коды через `exception_handler` FastAPI.

### 1.2. FastAPI, HTML и Pydantic v2
- **Lifespan:** инициализацию и закрытие клиентов (БД, `redis.asyncio`) выполнять через `lifespan` в `app/main.py`, а не устаревшие `@app.on_event`.
- **Разделение слоёв (SOLID):** роуты (`main.py` / `routers/`) занимаются только HTTP и рендерингом Jinja2-шаблонов; бизнес-логика — в `services/`, работа с БД — в `repositories/` (или `database.py` на этапе MVP).
- **Валидация URL:** проверять входящие ссылки через Pydantic (`HttpUrl` / кастомный валидатор) и разрешать только схемы `http` и `https`.

### 1.3. Redis: три сценария использования
1. **Sliding Window Rate Limiter:**
   - Хранить временные метки запросов в Sorted Set (`ZSET`).
   - Выполнять очистку старых записей (`ZREMRANGEBYSCORE`), подсчёт (`ZCARD`), добавление (`ZADD`) и обновление TTL (`PEXPIRE`) **атомарно** через Lua-скрипт, чтобы исключить гонку данных (race condition).
2. **Кэширование (Cache-Aside):**
   - Кэшировать пару `short_code -> original_url` с обязательным `TTL` (`SETEX` / `SET ... EX`), чтобы не переполнять память и не отдавать протухшие ссылки.
   - При обновлении или удалении ссылки инвалидировать ключ в Redis.
3. **Блум-фильтр (Bloom Filter) для антиспама в рамках сессии:**
   - Использовать для быстрой проверки, отправлял ли пользователь конкретную ссылку в текущей сессии (`session_id` в ключе).
   - Инструменты в Redis: модуль **RedisBloom** (`BF.RESERVE`, `BF.ADD`, `BF.EXISTS`) или компактная реализация на стандартном Redis через несколько хеш-функций и `SETBIT` / `GETBIT` с TTL на ключ сессии.
   - Помнить о компромиссе: Bloom-фильтр экономит память ($O(1)$ по времени), но допускает небольшой процент ложноположительных срабатываний (false positive rate, например `0.01`).

### 1.4. Celery и Docker / uv
- **Celery:** передавать в задачи только сериализуемые примитивы (`link_id`, `short_code`), а не ORM-объекты; делать задачи идемпотентными и настраивать `autoretry_for` с `retry_backoff=True`.
- **Docker:** multi-stage сборка на базе официального образа `uv`, запуск от non-root пользователя, наличие `HEALTHCHECK` и разделение сервисов (`api`, `worker`, `redis`, `db`) в `docker-compose.yml`.

## 3. Разбор кода и как его можно исправить

При анализе кода агент показывает **узкое место**, объясняет **сложность или риск** и подсказывает **инструмент языка/фреймворка**, который пользователь может изучить и применить.

### 3.1. Оптимизация алгоритмов: например $O(n^2) \to O(n)$ или $O(\log n)$
- **Симптом:** проверка уникальности или поиск элемента в `list` внутри цикла (`if url in seen_urls`), либо линейный перебор отсортированных временных меток.
- **Куда смотреть:**
  - Для проверки вхождения в памяти — `set` / `dict` ($O(1)$ в среднем вместо $O(n)$).
  - Для поиска по отсортированному списку — модуль стандартной библиотеки `bisect` ($O(\log n)$).
  - Для проверки спама ссылками в Redis — **Bloom Filter** ($O(k)$ хешей = $O(1)$ по времени и минимальная память вместо хранения всех строк в `SET`).

### 3.2. Атомарность в Redis: отдельные команды → Lua-скрипт
- **Симптом:** последовательные `await redis.zremrangebyscore(...)`, `await redis.zcard(...)`, `await redis.zadd(...)` в Python-коде.
- **Проблема:** между `zcard` и `zadd` другой асинхронный запрос может прочитать старое значение и превысить лимит (race condition).
- **Куда смотреть:** метод `redis.register_script(...)` (Lua-скрипт выполняется в Redis атомарно как единая операция).

### 3.3. Блокирующий код в FastAPI → Async / Threadpool / Celery
- **Симптом:** вызов `time.sleep()`, синхронного `redis.Redis` или долгой записи аналитики внутри `async def` эндпоинта.
- **Проблема:** блокируется event loop FastAPI — все остальные пользователи ждут.
- **Куда смотреть:**
  - Для I/O в реальном времени (редирект, кэш, rate limit) — асинхронный клиент `redis.asyncio` и async-сессии БД.
  - Для редких неизбежных синхронных вызовов — `fastapi.concurrency.run_in_threadpool`.
  - Для фоновых операций (подсчёт кликов, очистка старых ссылок) — вынос в **Celery**.

### 3.4. Повторное создание объектов и N+1 запросы → DI и Eager Loading
- **Симптом:** создание подключения к БД/Redis внутри каждой функции или обращение к связанным таблицам в цикле.
- **Куда смотреть:**
  - Инъекция зависимостей через `FastAPI Depends` + `Annotated` (единый пул соединений из `lifespan`).
  - Жадная загрузка в SQLAlchemy (`selectinload` / `joinedload`) или SQL-агрегация (`func.count`).

### 3.5. Идиомы Python (Stdlib вместо «велосипедов»)
- Генерация коротких кодов: криптостойкий `secrets.token_urlsafe` или Base62-кодирование ID вместо `random.choice`.
- Подсчёт статистики в памяти: `collections.Counter` и `collections.defaultdict` вместо ручных циклов со словарями.
